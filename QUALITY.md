# Code quality

`npm run check` verifies the repository. `npm test` runs unit coverage and the Worker integration
suite. The lockfile pins the tools. The checks inspect code without running submissions. The
integration suite executes one trusted recipe fixture in a temporary consumer project.

In Bist Settings, maintainers can set `off`, `warn`, or `error`. ESLint JSON accepts
`rules`, `globals`, `settings`, and `overrides` keyed by `source`, `interface`, or `tests`.
A part's rule overrides the recipe-wide setting. Enable **Block submissions with warnings** to
require a clean submission. Otherwise warnings accompany submissions and human review continues.
JSDoc remains an error even if previously saved settings or a part override specify another level. Other saved rule selections are preserved. Legacy policies inherit new checks where no rule was configured.

The checks exclude generated output and installed dependencies. Markdown handoff text is kept as
received. Migrations are exercised against SQLite-compatible D1 in the integration suite. Project
checks use static, explicitly scoped rules rather than inferring a layer or a translation contract
from arbitrary submitted code.

The repository Prettier config enables the local `blankLinesBetweenDeclarations` option for
JavaScript and TypeScript. It adds a blank line between adjacent declarations, before any JSDoc
attached to the next definition. Overloads stay together. Recipes use the same spacing by default.
Maintainers can toggle **Blank lines between declarations** under **Settings → Prettier**.
